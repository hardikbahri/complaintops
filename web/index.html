Portfolio project · end-to-end machine learning

Triage consumer complaints, and know when not to trust the model.

A fine-tuned DistilBERT sorts 335,000 real CFPB complaints into 24 product and issue classes. When it is unsure, an agent looks up similar past complaints, has an LLM write a short note, and sends the case to a human reviewer with the likely labels. Every model change passes an automated evaluation gate.

How it works

Six stages, each with a measurable check. The pipeline was built to be re-run, not just demonstrated.

    Results, honestly reported

    Complaints are split by date: train on the past, tune on a later period, and score the finalists on the newest complaints. Weighted F1 is the headline metric (each class counts in proportion to its size); macro-F1 sits next to it in the table views.

    The evaluation gate

    A new model replaces the champion only if it passes three automated checks on the held-out test set. The gate runs on the model's original 26-class outputs; the 24 served classes are a fixed merge of them. To prove the gate works, a deliberately weaker model was blocked and the real candidates were promoted.

    When should the agent trust the model?

    A classifier's confidence is only useful if it means something. This checks it on validation complaints, which the model never trained on, and sets the agent's threshold from the data.

    Drift monitoring

    In production the true label arrives late or never, so the monitor watches proxies: how different the text looks, how the predicted classes shift, and how sure the model is.

    Small enough to run on a free server

    The LoRA adapter was merged into DistilBERT, exported to ONNX and quantized to 8-bit integers, then benchmarked on 500 complaints using 2 CPU threads, about what a small free host provides.
